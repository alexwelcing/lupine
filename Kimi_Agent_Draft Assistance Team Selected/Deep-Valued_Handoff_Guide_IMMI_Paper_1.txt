## 2. The Extraction Boundary (What Ships vs. What Stays)

### GOES IN THE PAPER (Manuscript + Supplementary)

| Component | Inclusion Criteria | Where It Lives |
|-----------|-------------------|----------------|
| **Core Thesis** | Hyper-ribbon manifold exists across classical potentials and foundation MLIPs for a specific, matched-n element set | Manuscript Abstract + Introduction |
| **Final Element Set** | The exact subset validated. Name them. Count them. | Methods + Results |
| **Benchmark Data** | The distilled CSV/JSON that produced the figures | Zenodo release (get DOI), cited in Data Availability Statement |
| **Figures** | 4–6 main figures, 2–3 supplementary | Separate high-res files + embedded in manuscript |
| **Methods** | Hyper-ribbon construction, distance metric, dimensionality reduction, statistical controls (matched-n, bootstrap) | Methods section; point to repo for full code |
| **Compute Summary** | Table of experiments run, not raw logs | Methods or Supplementary |
| **Data Availability Statement** | Zenodo DOI + GitHub repo URL + Google Cloud/Cloudflare access notes | End of manuscript |
| **Cover Letter** | 1 page. Novelty claim, no simultaneous submission, no preprint, suggested reviewers | Upload separately in Editorial Manager |

### STAYS IN THE REPO (Cited but Not Published)

| Component | Why It Stays Out | How to Reference It |
|-----------|-----------------|-------------------|
| Full 559-potential corpus | Too large, too raw | "Full potential corpus available at [repo]" |
| Phoenix observability wiring | Infrastructure, not science | Mention in Acknowledgments if helpful |
| LUPI viewer code (`atlas/`) | Software artifact | Cite `lupi.live` as inspection tool, or write separate software paper |
| Agentic loop (`glim-think/`) | Methodology infrastructure | Not cited unless the paper itself is about agentic research |
| Sloppy-models deep-dive (`docs/sloppy_models_report.md`) | Background reading | Cite as related work; move to supplementary only if essential to the argument |
| Conjecture ledger / changelog | Living document | Freeze a snapshot tag if needed for transparency |
| Lean proof attempts (`lean-spec/`) | Formalization work in progress | Cite as ongoing work; do not block submission on completion |
| All intermediate/failed experiments | Clutter, scope creep | Delete or archive in a `scratch/` or `archive/` branch |

**Golden Rule:** The paper tells ONE story. The repo tells the whole research program. Do not confuse the two.

## 3. Critical Decisions Requiring Commander Sign-Off

These are blockers. Do not proceed past any of these without explicit approval from the Mission Commander.

### Decision 1: The Final Element Set
- **Question:** Which elements are in the validated subset?
- **Why It Matters:** This determines the scope claim. "We tested 12 elements" is different from "we tested 47." The abstract and methods must agree.
- **Action:** Data Archaeologist extracts the exact list from the approved experiment series. Manuscript Curator locks it in.

### Decision 2: Figure Roster
- **Question:** Which 4–6 figures tell the story? What is the narrative order?
- **Suggested Roster:**
  1. **The Hyper-Ribbon Itself** — 3D or 2D projection of the error manifold
  2. **Cross-Potential Comparison** — Classical vs. MLIP error geometry overlay
  3. **Validation Against Ground Truth** — DFT or experimental comparison showing the geometry predicts real error
  4. **Statistical Robustness** — Bootstrap or matched-n control showing the structure isn't a sampling artifact
  5. **Element-wise Error Map** — Heatmap or scatter showing which elements drive the geometry
  6. **Stiff/Sloppy Spectrum** — Eigenvalue or singular value plot showing the dimensionality
- **Action:** Figure Marshal presents draft roster. Commander approves. No figure gets cut after approval without replacing it.

### Decision 3: The "In Press" Typo Fix
- **Question:** What does the library site say instead?
- **Correct Language:** "Submitted to Integrating Materials and Manufacturing Innovation (IMMI)" or simply remove the line until acceptance.
- **Action:** Library Fixer commits and pushes. Do not submit to IMMI while the public site claims the paper is already accepted.

### Decision 4: Zenodo Release Scope
- **Question:** What exactly goes into the Zenodo release?
- **Rule:** Only the data that produced the figures in the paper. Not the full 559-potential dump. Not the raw trajectories. The distilled, analysis-ready dataset.
- **Action:** Data Archaeologist packages it. Portal Operator gets the DOI.

### Decision 5: Word Count & Supplementary Split
- **Question:** Is the manuscript >8,000 words? If so, what moves to supplementary?
- **Heuristic:** Methods deeper than 2,000 words → supplementary. Extended error tables → supplementary. Mathematical proofs → supplementary (unless they are the paper's core contribution).
- **Action:** Manuscript Curator measures and proposes cuts. Commander approves.

## 5. IMMI Technical Requirements Checklist

**Abstract**
- [ ] 150–250 words
- [ ] No undefined abbreviations
- [ ] No citations
- [ ] Stands alone

**Manuscript**
- [ ] American English
- [ ] Title page with author name, affiliation, corresponding email
- [ ] Figures embedded in manuscript AND uploaded separately
- [ ] Line art: ≥600 dpi
- [ ] Photos: ≥300 dpi
- [ ] Halftone + line art: ≥600 dpi
- [ ] Figure width: 39–174 mm (column to full page)
- [ ] Data Availability Statement included

**Cover Letter**
- [ ] 1 page
- [ ] States novelty
- [ ] Confirms no simultaneous submission
- [ ] Discloses preprint status (none, in this case)
- [ ] Suggests 3 reviewers (optional but recommended)

**Supplementary Material**
- [ ] Compiled into single PDF
- [ ] Labeled: "Supplementary Material for: [Title]"
- [ ] Includes extra figures, tables, extended methods

**Data**
- [ ] Deposited in Zenodo with persistent DOI
- [ ] Cited in Data Availability Statement
- [ ] GitHub repo referenced for code

## 6. Risk Register & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Repo is too messy to extract clean dataset in time | Medium | High | Pre-identify the exact file paths now. Do not browse. Know the filenames. |
| Figures are not export-ready (low-res, wrong format) | Medium | High | Figure Marshal starts exporting immediately. Do not wait for final text. |
| Abstract is too long or has citations | Low | Medium | Manuscript Curator checks this first. Cut aggressively. |
| Reference list has broken DOIs or ghost citations | Medium | Medium | Reference Auditor runs automated link checker. |
| Editorial Manager portal has technical issues | Low | High | Portal Operator registers early. Do not wait until Hour 6. |
| Commander changes scope mid-process | Medium | High | Lock decisions in Phase A. Any change requires formal override with new tag. |
| "In press" typo is seen by IMMI editor | Low | Critical | Library Fixer fixes this in Hour 0. Top priority. |

## 9. Final Directives

1. **Speed beats perfection.** A good paper submitted today is better than a perfect paper submitted next week.
2. **The paper is not the repo.** Extract ruthlessly. The repo's value is in the research program; the paper's value is in the single claim.
3. **No new experiments.** Do not run new code today. Only publish what is already validated.
4. **No new formal proofs.** The Lean spec is ongoing work. Mention it in the paper as future direction if needed, but do not block submission on proof completion.
5. **The submit button is sacred.** Only the Mission Commander clicks it. Everyone else prepares the runway.
