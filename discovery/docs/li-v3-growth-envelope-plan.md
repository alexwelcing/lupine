# Li v3 separate local-growth envelope contract

This profile is a bounded read-only compatibility extension, not scientific
admission. Root froze its scope before implementation. No prior reader is
modified and no new scientific observation, evaluation allocation or physical
claim follows from generated fixtures. Actual operations require reviewed
source/test/contract publication, exact CI, clean retained package and independent
artifact checks. This candidate does not authorize its own actual invocation.

## Existing prerequisite and same-buffer check

The sole receipt prerequisite is the existing G29 run-1 canonical public
receipt, SHA-256 `52fe2d25f0c739c1c5137f0514f07f4ee0be35dffd7ef9141b19fe5ee5520d2e`,
produced by `d0505b9b358a4bdeafbd742f1aeeb6c2b955abf3`. It establishes only
one selected field ID A220 and declared data size 516. G30's frozen validator
checks that exact receipt. No future G30 result hash is guessed, required or
substituted for a current-buffer predicate. Original capture identity and source
bytes/MD5/SHA-256 are verified separately before interpretation.

G29 `_inspect` and G30 `_result`/`_inspect_payload` inspect the same immutable
bytes object subsequently supplied to the new full traversal. Production
requires the computed selected fields to equal G30's exact observed A220/516
prerequisite. It proceeds only after the G29 and G30 reasons, all positive shape
booleans, completed payload interpretation and successful predecessor archive
cleanup agree. Any mismatch stops before the new archive is opened. G30's real
`diagnose` and synthetic public API are not invoked to perform this step.

The synthetic API rejects captured source identities and uses generated bytes.
It permits other bounded generated A220 sizes to test the predicate. It retains
the selected-span applicability gate: an archive with no nonempty local-extra
area remains blocked even if the older profile could accept it. Empty local
areas are allowed in other entries of an otherwise applicable archive.

## Complete header traversal

The new header routine is a source copy of the frozen compatible-envelope
predicate with only its nonempty-local-extra rejection removed. Every old
central/header/name/member/type/version/flag/method/size/CRC/timestamp/offset,
contiguity, directory and required-member predicate remains. Central extra
fields and comments still reject. Stored members retain equal sizes; method-8
option bits are allowed only under the existing method/flag rule. Encryption,
unsupported kinds, nonregular files, directories and unsafe names remain blocked.

An approved pre-actual scope addendum adds raw central-directory declaration
checks before constructing the new archive. The first generated author run
found an inherited structural gap: a final nonzero declared comment length
with no comment byte could be accepted when the underlying library returned
an empty truncated comment. The original failing fixture and run are preserved;
this is a parser validation finding, not a scientific result. The added preflight
bounds exactly the declared count of fixed central headers and their signatures,
each declared name/extra/comment span, and exact directory-end consumption.
Nonzero declared central-extra or comment lengths reject independently of any
library truncation. It decodes no text and publishes no metadata values. All
older source files and predicates remain unchanged.

Only after the original same-entry bounds and identity checks pass is a nonempty
local-extra area inspected. Every such area must contain exactly one complete
little-endian TLV: identifier A220, declared length at least four, and total
`4 + length` exactly equal to the bounded local span. The payload's first two
words are read as unsigned 16-bit values. The signature must equal A028; the
initial-padding value is withheld with semantics UNBOUND. Every remaining
payload byte is scanned and must be zero. The whole bounded remainder is visited
even if an earlier byte is nonzero. Empty current padding is permitted; no
initial/current equality, positivity or producer-history constraint is invented.
Unknown, duplicate, additional, truncated or malformed records reject. No source
bytes are rewritten or stripped. Limits remain 128 members, 183878 source bytes
and a 65535-byte local-extra span.

A holder receives each successfully constructed new `ZipFile` immediately,
before `infolist` or later validation can fail. The outer owner closes it on
header, XML, success and failure paths. Cleanup failure is a closed
`ARCHIVE_CLOSE_FAILED` category, forces engineering `BLOCKED_CLEANUP` and clears
projected envelope approval/role/count fields. The previous validation reason
is retained separately. The in-memory handle is detached after failed close to
avoid a subsequent destructor close attempt under the normal owned `ZipFile`
lifecycle. This does not promise control over arbitrary monkeypatched destructors.
No raw exception strings are published.

## Four unchanged XML members and closed projection

After every ZIP predicate succeeds, only the four original envelope members
are opened and parsed: `[Content_Types].xml`, `_rels/.rels`, `xl/workbook.xml`,
and `xl/_rels/workbook.xml.rels`. The original `_xml`, `_content_types`,
`_relationships` and `_workbook` helpers and their limits are reused unchanged.
Their existing documentary-role projection is retained. No worksheet or shared
string is decompressed or decoded; no arbitrary sheet name, formula, measurement
value or dictionary cell is published. ZIP metadata and those four XML members
are real additional machine exposure if actual production reaches them.

The public schema is `lupine.discovery.li_v3.growth_envelope.v1`, profile
`li_v3.xlsx_envelope.local_growth_hint.v1`. Scientific status remains
`BLOCKED_SCHEMA`; operational identity/read/write/source-guard failures are
`BLOCKED_GUARD`. `archive_profile_accepted` is true only after complete envelope
checks and successful cleanup. This means compatibility with this declared
profile, not general ZIP/OPC completeness, producer authentication or scientific
schema validity. Rows, pairs, source groups and overlap are null; overlap is
NOT_ASSESSED, fits/splits zero and initial-padding semantics UNBOUND.

The report preserves separate lifecycles. `selected_growth_check` contains only
closed G30 shape/reason fields, while `exposure.selected_growth` retains that
stage's G29/G30 exposure. These earlier bounded results may remain present after
a later failure; they are not envelope acceptance. Nested raw acquisition flags
are false because that predicate receives the already acquired buffer; they do
not negate the outer report's whole-buffer exposure.

The outer exposure records `central_directory_preflight_started` and
`central_directory_preflight_completed` separately. A raw declaration failure
uses `CENTRAL_DIRECTORY_DECLARATION_INVALID` and occurs before the new archive
opens, without erasing the separately recorded selected G29/G30 lifecycle.
It also records archive-open, directory-decode, complete-header and
archive-close starts/completions, plus any cleanup error. Structural local-area
counts report areas started/completed, completed fixed-word **pair** decodes,
and padding scans started/completed. They are software read-progress counts,
not scientific samples or row counts. `local_growth_payload_interpretation_started`
means at least one area's fixed payload words were attempted; its completed flag
requires the entire full-header traversal to succeed. A later failure preserves
all earlier counts and flags without asserting overall completion. XML helper
lists preserve per-member decompression/decoding starts and completions, including
partial failures. No local payload word, pad value, payload hash or raw byte dump
is disclosed.

## Production identity and output bounds

Production inherits the immutable G30/G29 source guards and pins all four frozen
G30 source/test/contract files. It binds its own script, author test, independent
test and this contract to canonical committed HEAD and index bytes. No alternate
path, URL, producer, receipt, source object, profile or cap is accepted.

CLI is `li_v3_growth_envelope.py envelope --run 1` or `--run 2`, always exit 2
because scientific schema is blocked. Outputs are fixed exclusive public slots
under `.cache/li-v3-custody/growth-envelope-v1/{1,2}/public.json`. The inherited
contract prevents overwriting completed slots and rejects sequential reuse
before another source read. It does not promise concurrent at-most-once reads.
Output/write/descriptor-close failures retain any already observed exposure and
cannot leave envelope acceptance true. A public file written before a later
output-close error may differ from returned stdout; an operation recorder must
preserve and compare both rather than silently treating either as successful.

The author suite exercises generated archives only; production guards and
source operations remain uninvoked in author preparation. Independent tests
and review may challenge production control flow only with complete synthetic
injections and no actual private reads. Actual source acceptance remains unknown
until a separately authorized, fully gated production invocation completes.
