# Prospective archive driver and registered launcher

This is an implementation under synthetic review, not an actual study result or
permission to allocate the real 75 groups or read performance targets. The
original scientific protocol and implementation contract remain unchanged. The
separate operational-enforcement addendum governs monitored RSS, cumulative
wall time, network isolation and outer failure classification.

## Module boundaries

- `mpea_study_flow.py` contains the scientific loop extracted from the reviewed
  fixture driver. It opens no files or entropy source. The unchanged study kernel
  alone predicts, ranks, calibrates and audits. The fixture wrapper still requires
  `FixtureCase` and the unchanged parser's actual-source SHA rejection.
- `mpea_production_store.py` persists anchored, no-overwrite envelopes. It does
  not authenticate registration, validate scientific payloads, or authorize source
  access. Its original-allocation import preserves both original artifact bytes
  and all seals. Attempt kind is a separate immutable marker.
- `mpea_archive_custody.py` authenticates the registered route/feature inputs,
  owns captured mixed source bytes and role-separated vaults, and exposes bounded
  capabilities. Production reuses only the frozen parser's source-free
  `_authorized_cells` and `parse_target`, after independent registration/source/
  route checks. It never substitutes a real identity into `FixtureSource`.
- `mpea_archive_driver.py` connects those capabilities to the shared loop and
  enforces source snapshots and registered-manifest checks at stage boundaries.
  `run_synthetic` is a separate constructed-data route. There is no source-path,
  seed, target-column, split, predictor or threshold override on that route.
- `mpea_archive_report.py` joins issued driver results to the unchanged public
  projector. It is not another scientific evaluator. Result/projection bindings
  prevent ordinary object replacement, mutation or cross-attempt publication.
- `mpea_archive_worker.py` requires the supervised marker descriptor, promoted
  main-tree origin and a parent-authenticated registration capture. The parent
  entry `mpea_archive_run.py` authenticates live official registration/CI evidence
  and explicit reviewed engineering identity before launching the fixed worker.

Registration/allocation, mathematical kernel, public projector and supervisor
remain separately owned and reviewed components. Registration factory modes for
original and fixed-allocation reproduction are distinct. A synthetic registration
cannot authorize production, and an ancestry-based reproduction authority cannot
request a fresh allocation.

## Data access and immutable stages

The parent reads registration, registered source/engineering/CI files and public
metadata evidence, but not the source CSV or local feature table before launch.
It checks feature-path syntax and symlink ancestry before consuming the single
allocation attempt. The worker first verifies the exact parent capture, loads
pinned public metadata and seals all1545 row routes and the allocation. It then
loads only the exact local feature artifact identity recorded by the two public
feature-readiness receipts and their reproduction evidence. It reuses the frozen
feature reader's validators and reconstructs vectors using the study kernel's
own `NormalizedVector` class. This explicitly handles the reader's representation
module reload without changing the frozen reader.

The input freeze contains the full1,545-row membership and all314 selected
feature records, the closed feature/header/metadata profile, full original-role
counts and source-token, lexical-formula, normalized-composition and combined-
descriptor cross-role equality aggregates. Unknown compositions are not grouped
as one zero vector. No equality finding changes roles or removes a row.

The ACKed `TARGET_PHASE_BEGIN` occurs before the development decoder. The source
file is captured once, through bounded no-follow file/directory descriptors.
Size, MD5 and SHA256 must all match before framing or target conversion. Mixed
bytes necessarily cross the custodian; they are not described as unopened.
Framing scans the whole source and finishes its count/width checks before any
selected target is interpreted. Only authorized role+condition cells in columns
11 and13 are accumulated. Non-T25 rows sharing an active source remain unopened
at the target-cell decoder.

Development labels and their explicit provenance are sealed in the separate
`development-targets.json` companion. Its persisted bytes and original target
join are verified before the model receives labels. An inadequate
50-row/15-source development set produces a durable NO_GO and no fit/reserved
access. Otherwise all314 predictions and75 full panel rankings are sealed before
role-blind parsing of the40 reserved panels. Both target vaults bind that rank
freeze, their source framing and the per-label source/parser/column identities.
`secondary-membership.json` retains all40 groups including empty panels;
`completeness.json` exposes only the declared aggregate counts and references. The calibration consumer opens only its own numerical vault; it can see
the fixed completeness manifest and all40-defined boolean. All40 future pool
receipts across both populations are sealed before an evaluator is issued.

Each policy receives one bound `PolicyOracle` without a policy-selector argument.
Requests must match its next fixed prefix. Tokens are one-use object capabilities;
copied, foreign-policy and foreign-attempt tokens fail. The full evaluation truth
is exposed for audit only after all960 policy runs finish and the replay ledger
is sealed. Partial policy completion and actual bundle requests are counted
separately; missing parse/visibility counts remain unknown when a failure prevents
measurement. A complete execution is not necessarily a usefulness GO.

## Bindings and publication

Archive cases contain immutable feature/identity snapshots and are issued by
validated factories. Before decoder entry, the custodian reconstitutes the input
payload from current typed features/routes and compares it to the sealed payload.
Copied dataclass authority fields alone do not make an issued case or result.
This is ordinary API capability integrity, not protection from hostile Python.

All stage status/reasons/access/payload belong to scientific identity. Usage is
excluded. Registration protocol, contract, operational amendment and implementation
manifest belong to scientific identity; engineering/CI/registration-wrapper hashes
remain content-bound. Vault whole/content/scientific identity triples are explicit
`reserved.inputs.calibration_vault` and `evaluation_vault` entries; the reserved
payload contains only each vault's scientific identity. There is no generic
recursive removal of payload hashes. Original and reproduction use the same
registered scientific scope. Synthetic scope stays distinct.

The projector receives issued typed results and exact upstream aggregates. Its
output retains no original record IDs, targets, feature vectors, neighbors,
orders or predictions. The sink accepts only the projection issued for that exact
unchanged result. Result issuance binds the identities recorded at successful
stage writes without reopening potentially damaged files. Validation before
projection or publication verifies the entire persisted prefix; corrupt evidence
can therefore yield a typed `BLOCKED` return but cannot authorize a public report.
An inadequate or interrupted attempt with a valid prefix has an unavailable report
without performance verdicts. Complete negative findings remain complete reports.

The parent accepts success only after the supervisor's successful terminal. It
compares captured supervisor bytes to the returned operational body, verifies the
actual persisted stage envelopes/seals and predecessor chain against ACKed stage
markers, and checks the closed outer public transport, its recomputed seals and
its final verdict's link to the sealed evaluation. It does not reconstruct a
model or independently recompute aggregation from public seals. After completion,
this persistence verification parses private stage receipts; it is not described
as a public-metadata-only audit. A locally complete public file does not override
supervisor failure. Reproduction mismatch clears the launcher's scientific verdict.

## Literal contract records and resource observations

The closed profile/artifact helpers project existing evidence; they do not fit,
rank or calibrate. Both endpoint provenance records distinguish an exact known
value from an unresolved label. Uncertainty remains `NOT_INTERPRETED` and pairing
remains `CO_RECORDED_NOT_SPECIMEN_VERIFIED`. The aggregate `rank-summary.json`
binds the actual rank-stage scientific seal, counts and fallbacks without record
IDs, predictions or orders. A prospective seal is checked against the committed
stage before reserved access; the summary is not an input to its own referenced
stage. The complete declared companion graph is authenticated before publication.

`mpea_archive_decisions.py` preserves each original generic decision's scalar and
tuple fields. Original calibrations and future panels live in named shared tables
with explicit digest joins. The compact compatibility projection must match those
original typed plans; validation reconstructs identities without selecting a new
pool. Semantic references include the source, columns, parser and rank seal; the
calibration outcome additionally binds its original vault's scientific seal.

Every stage records wall/process CPU clock differences and explicitly scoped RSS
observations. The observer ends before that stage's publication/marker ACK; input
observation starts before feature validation. Boundary RSS and the process-lifetime
high-water mark are distinguished. A true within-stage RSS peak is unavailable,
not estimated or presented as zero. The separate unchanged supervisor enforces
its declared target-phase wall and sampled process-tree RSS limits. Reproduction
preserves original allocation/route bytes; import cost is recorded separately.

Every companion explicitly attributes its resource work to the enclosing stage;
its separate duration/CPU/peak fields are null and marked not separately measured.
The descriptor creates no circular stage seal. Companion construction/publication
occurs inside the measured stage window; a missing stage observation remains
unavailable. The complete access and usage views are checked at dependent consumer
gates and during final persisted-evidence verification.

Access records distinguish mixed-source capture from role-bundle accumulation,
decoding and interpretation. They name the actor, stage, authorized columns and
counter scope. A phase started without a completed observation has unknown counts.
Target companions report completed authorized-role snapshots and actual cumulative
source captures separately. Rank-summary zeros describe its local projection work;
allocation zeros describe the pre-target state. The parent later parses private
receipts to verify persistence; these counters do not assert that only the worker
can ever see those receipt contents.

The launcher exposes the closed outer study status/reason separately from its
bound internal operational cause. Marker failures map to the contract's stage
order violation; otherwise unknown failures remain `INTERNAL_FAILURE`. A trusted
kernel arithmetic-limit reason is preserved. The reproduction report separately
compares each declared artifact's full bytes/content and scientific identity.
Usage can change full-file bytes without changing scientific seals. Equality of
partial maps cannot establish complete-study reproduction.

## Entry points after registration publication

These commands are prospective; no actual invocation was performed while writing
this implementation. The registered implementation, protocol/addendum, source-
bound engineering receipt and green CI must first be published and authenticated.
The launcher must run from its promoted main-tree path, not this scratch copy.

```sh
python scripts/mpea_archive_run.py \
  --registration /absolute/path/to/registered-request.json \
  --engineering-sha256 REVIEWED_ENGINEERING_FILE_SHA256 \
  --feature /absolute/project/discovery/.cache/mpea-features/verified/local.json \
  --attempt archival-original-001
```

A new process reuses the original allocation and durable first-draw ledger:

```sh
python scripts/mpea_archive_run.py \
  --registration /absolute/path/to/the-same-registered-request.json \
  --engineering-sha256 THE_SAME_REVIEWED_ENGINEERING_FILE_SHA256 \
  --feature /absolute/project/discovery/.cache/mpea-features/verified/local.json \
  --attempt archival-reproduction-001 \
  --original-attempt archival-original-001
```

The reproduction route verifies captured original allocation/routes and the fixed
protocol/source ledger; it imports the original bytes and requests no entropy.
A later branch may require an isolated checkout of the registered source. No
source, manifest, allocation, receipt or reference hash is silently rebased.
A reproduction is the same archived experiment, not an independent sample.

Outputs stay under `.cache/mpea-archival/<attempt>` and
`.cache/mpea-archival-launches/<attempt>`. Preserve incomplete/failed prefixes;
never overwrite or resume an attempt. The public report is a candidate for
separate reviewed publication, not automatically copied into the application.

## Engineering evidence scope

All author and peer tests use constructed source bytes and metadata. A special
fresh-process format simulation deliberately uses registered-format envelopes
with a fake source, tests unchanged allocation import and all scientific stage
identities, and asserts the registered public projector rejects that fake source.
It does not create production authority or bypass the frozen fixture parser's
real-SHA rejection. Initial test-fixture mistakes, source-drift interruptions and
producer findings are preserved with their corrections. Passing synthetic tests
is necessary engineering evidence, not an archival recovery result or physical
material qualification.
