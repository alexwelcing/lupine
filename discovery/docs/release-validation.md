# Release validation matrix

Snapshot: 2026-10-10. This matrix separates a usable research preview from a
scientifically supported recommendation release. A browser interface and known
answer examples are necessary product work; neither establishes physical
predictive reliability. A release must declare which property families,
conditions, candidate universe, and guarantee type its evidence supports.

`PASS` means the stated evidence exists at this snapshot. `FAIL` means an actual
experiment contradicted the required premise. `OPEN` means the gate has not
been established. A passing software gate cannot override a failed scientific
gate. No aggregate score averages away blocking failures.

## Bounded next scientific evaluation

Before examining more test outcomes, save a versioned task card with objective,
constraint semantics, units, conditions, permitted train/calibration sources,
features, exclusion rules, deterministic splits, surrogate hyperparameters,
measurement budget, metrics, and acceptance criteria. Pin the task-card digest.
Choose thresholds for the intended use before results are seen, and retain the
full report when a task misses them.

1. Add a source with jointly reported performance and feasibility properties
   under explicit operating conditions. The first constrained task must have
   known measurements for every candidate's score and each audited constraint;
   treat missing outcomes as unresolved, never as pass/fail labels.
2. Repeat a fixed protocol across independent chemistry families and provenance
   sources, then hold out one source or later publication cohort. Group
   equivalent compositions, molecules, and repeated measurements across splits.
   Verify identities with chemistry-aware tooling before claiming independence.
3. Specify the interval guarantee to be released. Deterministic guarantees need
   a justified physical enclosure construction. A probabilistic mode needs an
   explicit simultaneous risk budget and assumptions, with calibrated abstention
   under unsupported shift. Per-candidate marginal coverage is insufficient.
4. Compare against nominal ranking, random ordering, and an established scoped
   scientific baseline at identical labeling or experiment budgets. Measure
   all-optimum retention when meaningful, simple regret, feasible hit rate,
   pool size, constraint violations, and uncertainty. Distinguish ties within
   measurement uncertainty from exactly equal archived decimals.
5. Test whether evidence acquisition improves those metrics after each fixed
   budget, without peeking at unrevealed answers. Any adaptive tuning starts a
   new protocol and requires new held-out evaluation data.

## Release decisions

A research preview may ship once the interface, independent known-answer
oracle suite, clean packaging, and explicit failure/unknown presentation pass.
It must identify empirical intervals as unsupported physical premises and show
the failures above. That release is a tool for reviewing candidate evidence.

A scientifically supported recommender additionally needs the open scientific
gates resolved for its declared scope, and current failures addressed by a new,
independently evaluated interval construction or a narrower, honestly labeled
claim. Retrospective success can validate recovery of known answers; it cannot
prove that an unknown proposed material works before independent evidence.
