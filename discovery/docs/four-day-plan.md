# Four-day project contract

Requested by Alex Welcing on 2026-10-10. This is a work plan, not a claim that four
days have elapsed or a promise that an unattended process will continue after a
session ends. Resume from `STATUS.md` and the repository commits.

## Day 1 — universal decision kernel

Deliver an exact selector, general specification, machine-checked core theorem
modules, reproducible synthetic fixtures, versioned JSON input/output and tests.
Acceptance: tied optima retained; empty/no-incumbent cases explicit; exact regret;
compatible refinement; source/units checks; no admitted formal proofs.

## Day 2 — evidence and retrospective evaluation

Deliver archived-data adapters, pinned datasets, frozen development/calibration/
evaluation splits, equal-budget baselines, missing-outcome handling and replay
receipts. Run initial pilots during Day 1 when independent work permits.
Acceptance: the selector cannot access outcomes, no train/test identity leakage,
failed coverage and uselessly large pools reported, no new DFT necessary.

## Day 3 — richer recommendation and acquisition

Extend the verified set-based interface to Pareto dominance and selected nonlinear
property maps, with a theorem and a counterexample test for each extension. Compare
evidence acquisition rules by fixed evaluation budget. Investigate distribution
shift and simultaneous coverage separately from deterministic logic.
Acceptance: useful savings on frozen independent tasks, or a recorded negative
result. Heuristic acquisition is explicitly distinct from certified elimination.

## Day 4 — independent audit and release

Audit numerical encoding, formal axioms/dependencies, source rights, runtime/formal
conformance and end-to-end reproducibility. Cross-review claims against theorem
signatures and result artifacts. Publish a release with exact commands, limitations
and claim-to-evidence links. A passing build cannot substitute for scientific data.

## Completion gates

- General kernel: candidate representation and material family never hardcoded.
- Formal: kernel-checked source with no admitted proofs; assumptions enumerated.
- Scientific: no assertion of unconditional all-material accuracy.
- Empirical: held-out truth never selects model settings or development splits.
- Product: a candidate pool, regret certificate, refusal reasons and evidence needs.
- Reproducibility: immutable upstream references, dataset hashes, deterministic CLI.

## Explicitly outside the first release

New DFT, synthesis, paid cloud jobs, production deployment, universal generation
of all matter, and certification of plant readiness. The UI remains secondary to
the recommendation engine. These exclusions do not prevent archived DFT replay.
