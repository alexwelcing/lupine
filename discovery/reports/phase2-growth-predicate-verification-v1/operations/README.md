The recorder requires an original push CI run with all four expected jobs successful at the exact commit, matching package/strict receipts, and independent artifact receipts binding 335 runtime files and the three additions to the unchanged 332-file baseline. Only `scripts/li_v3_growth_predicate_audit.py audit --run 1` then `--run 2` can run. Any existing recorder directory or either target run directory is treated as consumed, including partial/empty reservations. Source imports use an absent private bytecode prefix with bytecode writing disabled. The command environment removes inherited Python path/home overrides and uses the same absent prefix.

Exit 2 is the expected bounded diagnostic result, not a scientific pass. Run 1 must finish without timeout, stderr, guard/cleanup error or source drift. Its canonical closed stdout must equal the separately retained persisted public bytes. Both DIAGNOSTIC_COMPLETE and DIAGNOSTIC_INCOMPLETE are permitted when the fixed same-buffer predecessor gate reproduces. No particular first category or aggregate result is expected. The recorder checks the category vocabulary, status/dependency structure, exposure limits and fixed scope; it does not independently rerun the classifier or interpret raw source.

The returned stdout and a copy of any available public file are retained separately before accepting completion. This matters when a descriptor-close error changes returned status after a public write. On failure, raw logs, the saved public bytes, post-state results and a stopped record remain; unvalidated exposure is UNKNOWN rather than falsely zero. No retry or rerun is attempted. A second command is possible only after the first validated result and a fresh full state check; the final replay claim additionally requires byte-identical results.

The recorder itself reads only source/public gates and public result files. It never opens the private object or original capture. Only the separately committed, gated diagnostic performs its authorized bounded raw-buffer read. All scientific schema claims remain blocked, archive acceptance stays false, and member/XML reads, fits and splits remain zero.

Preparation performed AST parsing and compilation for syntax only. No project import, production guard, recorder/diagnostic invocation, raw/capture read or network call occurred. These are controlled-workflow safeguards, not a security boundary against arbitrary hostile code or directory owners. Root owns final binding, source review, actual execution, independent actual-result audit and publication.
