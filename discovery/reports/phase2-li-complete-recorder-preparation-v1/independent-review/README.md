# Independent prospective recorder review

This review reads recorder, helper, and public-validator source only. Executed checks extract individual function definitions and replace every external operation with generated in-memory stubs. No recorder/support/product module is imported, and no actual production guard, Git/remote command, package command, source operation, private input, archive or actual G34/custody receipt is accessed. The review changes no tracked file and grants no release or operation approval.

The initial held operation recorder was `6c8c9f96…`, its package helper `a03fc98c…`, and shared helper `6f02c0ed…`. Source review found two concrete ordering defects:

1. Historical public A/B prefix validation occurred only after the two new commands. A generated prefix that the public validator rejects reached both command stubs before the recorder stopped. Narrow prior packet checks did not substitute for the full public prefix review before new source access.
2. A stdout/stderr publication exception could bypass the post-child source/gate check and execution-receipt attempt, in both the operation and package helper. These checks must remain attempted even when log storage fails, and the failure must block success.

The first independent invocation preserved two failing assertions plus a reviewer-fixture error: its fake support omitted `LOG_CAP`. After adding only that missing constant, all three intended regressions failed against the same held source. Both invocations, exact source snapshots and logs are retained. A subsequent mock-only adaptation supplies the accepted pure `_expected` helper to the fake validator; the three rejection expectations are unchanged.

The corrected `c0c48570…` operation recorder and `ff75410b…` package helper passed those same three independent expectations. Their delta validates the supplied expected packet and prior public prefix before a command, records failed log publications, still attempts post-state and execution receipt retention, and requires an empty log-failure list for success and historical acceptance. The operation and package controls retain their existing timeout, phase, output and source gates.

A final helper read found one separate publication cleanup defect: the temporary file was closed after linking a success name, outside the guarded exception cleanup. A file-close error could leave that success name and skip remaining cleanup. A one-test, entirely virtual-descriptor regression demonstrates the failure at `6f02c0ed…`; no real descriptor operation is executed. The agreed repair closes the temporary file in guarded code before success publication and attempts remaining cleanup independently. A final parent-directory close can still leave an already published name, so later gates must require externally observed successful outer recorder completion rather than file existence. This applies to package completion as well as historical phase completion.

The final held operation recorder `f13ec4ad…`, package helper `ff75410b…`, and shared helper `6533ff3b…` resolve these findings. All four independent regressions pass (0.067 seconds unittest, 0.286 seconds recorded process time), with the exact sources and tests held before/after. No additional defect was found in the final source delta. The original failing probes and intermediate passes remain unchanged.

Both the package gate and historical phase acceptance now require four explicit outer-completion pins: execution receipt, actual stdout, stderr, and persisted final report. The closed receipt checks exact command/producer/binding, integer exit 0, literal completed/source/group-cleanup flags, false timeout/launch/overflow flags, ordered integer times, exact log sizes/hashes, and matching valid before/after state hashes. Actual stdout must equal the canonical persisted final bytes and stderr must be empty. Closed final payloads retain their correct package/phase identity and no-admission/no-retry scope. The documented root observer must retain the state preimages and its own witnessed successful return; a final marker is insufficient. These are root-observed evidence with root-authorized pins. Neither this source review nor arbitrary success JSON authenticates execution by itself.

The remaining static scope covers fixed phase/slot commands, the 2×3 limit with no dependent automatic advance, 345 runtime and eight owned file identities, worktree/index/HEAD and remote checks, original four-job push CI, retained package/strict/artifact bindings, no-follow bounded public paths, exact historical producers and lineage, and the public validator interface. Complete negative C remains an exit-0 engineering result with scientific admission false. Stdout is the reviewed CLI's post-close return serialization; it is compared to persisted public bytes and is never invented as an independent third observation.
