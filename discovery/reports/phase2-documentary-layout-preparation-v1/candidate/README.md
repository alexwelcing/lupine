# Pure documentary-sheet layout preparation

This candidate implements the prospective two-role layout inventory on generated
workbook bytes only. Its final author execution passed 33 tests after the
namespace-cap amendment; the earlier 31-test pass is preserved. The public pure
API is `inspect_synthetic_layout(raw)`; it has no production command, custody
reader, file output, network operation or production guard. Known actual source
identities are explicitly refused. Future production receipt/producer bindings
remain null. This is not evidence that the real workbook satisfies the profile
or contains either required role.

[scope.json](scope.json) was frozen before implementation. It binds the published
layout design and explicitly adapts the prospective envelope dependency from
the earlier blocked deflate-options profile to the separate reviewed G31 local
growth profile. The actual G31 result is not assumed. A later production stage
would need its own exact observed prerequisite, complete source/contract/tests,
independent review, publication, exact CI/package/artifact checks and separately
gated operation. This preparation supplies none of those actual-source claims.

The parent directory already contained older G23 diagnostic evidence. Exclusive
directory creation refused before any write; this work uses the fresh nested
`documentary-localization-v1` directory. The nine earlier files are bound in
[historical-directory-preservation.json](historical-directory-preservation.json)
and are not replaced. The manual ZIP builder reuses the same author's G31

## Implemented structural contract

The same immutable generated archive buffer passes the G29/G30 selected growth
predicate, complete G31 raw central/local header validation and the unchanged
four envelope XML validators. The validated workbook tree and worksheet
relationship map remain in memory. Both exact roles are resolved through their
namespace-qualified relationship IDs; ordinal and `sheetId` are never used to
guess a member. Existing content-type validation applies and role members must
be distinct. Only the four envelope members plus those two worksheets may be
opened. Shared strings and other member contents remain unopened.

A separate streaming XML target implements the published finite worksheet
grammar. It retains bounded structure, coordinates and declarations without
retaining character-data callbacks. Strict UTF-8 decoding occurs first and is
tracked separately from XML parsing and structural traversal. Node/depth and
attribute caps apply as events arrive, before adding to scanner state; no
general spreadsheet loader, formula evaluator or numeric value converter is
used. XML text processing may privately expose inline text, values, cached
results and formulas. The public report does not claim those bytes were unread.

An independent source review identified that ElementTree omits namespace
declarations from its ordinary expanded-attribute callback. Root approved the
[pre-edit scope addendum](namespace-cap-scope-addendum.json): namespace callbacks
now count declarations together with ordinary attributes, bound lexical
`xmlns[:prefix]` names and URI values with the same 32/256/1,024 caps, and mark
structure traversal before a failing bound. Pending declarations reset exactly
at each element start. Used expanded names retain the original grammar and
unused declarations remain allowed within those caps. The earlier source,
31-test author pass and independent 26-test pass are retained; none was an
actual-source observation.

The projection contains all explicit cells, canonical coordinates, the closed
declared storage type (including `absent`) and formula-element presence, plus
canonical nonoverlapping merge rectangles. Sparse gaps are never expanded.
Both complete role inventories are published together or `roles` is null.
No header/definition/unit/reference or eligibility semantics are inferred.
Opaque content changes that retain an accepted layout and bounds produce the
same public report; this is not a guarantee against arbitrary hostile covert
channels or malformed-content changes.

The public `envelope_exposure` is exactly the design's twelve-field projection;
the older `inspected_xml_bytes` counter remains private. Its worksheet flags
describe only the envelope stage. New per-role read/decompression, UTF-8 decode,
XML parse and traversal starts/completions describe the later worksheet work.
The character-data state is set before decoding and retains completed decode
exposure after a later XML/structure failure. Archive cleanup failure clears
all layout approval, preserves the earlier closed reason and returns a closed
error. No raw exception message, member name, content length or content hash is
released by this pure API.
