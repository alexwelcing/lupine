# Li first flag-family diagnostic: reviewed engineering checkpoint

2026-10-16. The [actual prior header diagnosis](../phase2-workbench-verification-v1/README.md)
identified `MEMBER_FLAGS`, without revealing which flags or approving later
headers. This increment implements a separate source-bound diagnostic for that
same first failure. It preserves all nine frozen custody/header files and all
original failed receipts. **No actual flag-family run has executed at this checkpoint.**

The [contract](../../docs/li-v3-flag-diagnostic-plan.md) requires the original
capture/object identities and current committed/index/worktree source agreement.
There are only two fixed output slots and no URL/object/path override. The
unchanged header traversal must reproduce MEMBER_FLAGS on the same raw buffer;
only then does a second central-directory parse classify that first rejected
entry. It returns a closed family: encryption/masking present, method-8 option
flags only, supported-method descriptor declaration, or other/mixed flags.

The [standards note](standards/README.md) grounds those distinctions in PKWARE
APPNOTE 6.3.10. A data-descriptor declaration is not proof that a descriptor
exists or is valid. An option-only flag does not establish local-header
agreement, later-member validity or schema readiness. No mask in an original
reader is widened. The source's whole raw buffer would be read; no member
decompression/XML/worksheet interpretation is performed. Every classification
remains BLOCKED_SCHEMA, scientific counts null and fits/splits zero.
