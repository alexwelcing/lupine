# Prospective independent source-readiness challenges

This matrix is written before receiving the held candidate interface or execution results. It is a small engineering/claim-scope review. All forged inputs are generated; no archive, private custody, external source request or scientific evaluation is involved. Candidate execution begins only after explicit source/interface hold.

| Area | Independent challenge | Required behavior |
| --- | --- | --- |
| Complete public resource | Load the declared current negative/unknown records and inspect their claims | Source-operation blocks remain distinct from scientific performance results; no source or benchmark admission, physical truth, or freshness claim |
| Resource structure | Missing/null resource, malformed JSON, incomplete records, wrong schema/type and extra undeclared fields as the frozen contract specifies | Bounded invalid/unavailable response; no partially accepted or silently repaired scientific state |
| Claim forgeries | Set admission true; replace blocked/unknown state with ready/success; use bool-like integers/strings or contradictory phase counts | Reject the forged claim; preserve the difference between observed access failure and unknown scientific prerequisites |
| Exact wire equality | Compare the held CLI and HTTP JSON to the resource's declared public projection | Exact typed JSON equality, including nulls and explicit unknowns; no invented values or hidden claim strengthening |
| Missing/error after valid UI | Render valid resource, then null/missing/malformed response or failed refresh | Remove old cards/result and disable/remove old export; error cannot look like the prior result is current |
| Overlapping refresh | Where the loader permits overlap, delay an earlier response and finish a later invalid/failed response first | Earlier stale response cannot revive superseded cards or export; test actual callback completion, not only network delivery |
| Export identity | Export a valid displayed report, then mutate/re-render/clear | Download matches exactly the currently accepted object, detached from later caller mutation; invalid states cannot export prior bytes |
| Text injection | Generated HTML-looking names/reasons/documentary strings | Display literal text or reject invalid content; no executable DOM, event handler, navigation or remote fetch |
| URL injection | javascript:, data:, deceptive control characters and unsupported URLs in generated provenance fields | Reject or withhold active link according to the frozen contract; a safe display must not activate an unsupported URL |
| Browser semantics | Inspect status headings, summaries and keyboard behavior | Clear source-readiness versus science status, accessible readable blocked/unknown states, no misleading green ready indication |

Scope remains the resource, its existing local API/CLI integration and the small view. No general dashboard, authentication system, parser expansion, archive retry or new scientific allocation is proposed. A local synthetic browser/HTTP harness, if used, must block all external requests. Existing product and source data are not tuned.

The exact schema, adversarial cases and execution source hashes will be frozen after the interface arrives. Candidate authors retain ownership of their implementation; this lane writes only its own ignored review directory and preserves first failures.
