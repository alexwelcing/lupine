# Source-readiness workbench increment

The ignored overlay adds `web/source-readiness.js` and changes only the existing index, benchmark loader wiring and nine scoped CSS rules. The section follows the Rhizo stored-label census. It exposes no source-operation or retry control. Primary cards give plain blocked-status summaries; exact published actions, blockers, exposure, rights declarations and evidence links remain in keyboard-operable collapsed details. No source is scientifically admitted.

The renderer accepts only the complete `lupine.source-readiness.v1` public snapshot at commit `88d512cbf40a7a7d11fb45aa24cd5462f8a7e81d`: ordered IDs `li-tensile-v3` and `dryad-dielectric`, fixed blocked statuses and `NOT_ADMITTED`. Closed keys, bounded ASCII strings/arrays, safe HTTPS evidence links and the canonical SHA256 `74e8ca924e2eb4524aea2e54362bf78e88208fa8699cdb38a3ad795c91bf2c24` are checked before cards or exports appear. The backend fixture is preserved as `fixture.json`, raw SHA256 `9abad97d5675f416cc38a325bcd1e108825af001b2fdfccaa1f5c7dfb66f3f0b`. A digest establishes identity with reviewed documentary text, not scientific truth.

`window.LupineSourceReadiness.render(report)` returns a promise. It removes previous cards and export controls synchronously, then checks the detached snapshot with Web Crypto SHA-256. The normal loopback workbench is a secure context. Missing Web Crypto, missing/invalid/altered resources and the backend's explicit unavailable objects produce the same visible unavailable state. A generation token prevents a late digest or a retained old export button from restoring stale output. The app's separate request token also prevents an older fetch response from replacing the latest source-readiness state; other benchmark renderers and controls retain their existing behavior.

The export contains every field and value of the validated detached JSON object, indented with one final LF; it does not promise the resource file's whitespace or key order. Mutating the caller's object after rendering cannot change the export. Text is inserted through `textContent`; evidence links are restricted to the exact published GitHub snapshot and use `noopener noreferrer`.

`browser_checks.py` runs Chromium against the exact fixture and held assets, with all requests fulfilled in memory. It exercises the exact app `loadBenchmarks` function with unrelated renderer stubs for fetch races; this is not full-app or actual-server integration. Direct checks cover complete disclosure and export, keyboard/mobile behavior, missing/invalid/forged/injection cases, old-button and asynchronous-digest invalidation, and three out-of-order fetch cases. Root owns subsequent real HTTP integration, publication and CI. No target archive, private capture, source acquisition, source parser or scientific evaluation is used here.

The unexecuted pre-correction renderer draft is retained under `before-tensile-label/`. Its initial creep label was corrected from the published tensile-methods evidence before the first held browser run. Run receipts preserve first failures and source identities; a later pass must not replace them.
