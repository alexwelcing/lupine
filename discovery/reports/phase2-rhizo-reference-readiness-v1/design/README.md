# One bounded Rhizo reference-readiness pass

2026-10-16. **Preparation only; no raw object read or source operation has run.**
The next proposed step enriches the existing candidate-reference graph from two
already retained JSON objects. It does not execute Rhizo code, choose references,
calculate residuals, admit a benchmark or complete G21's paired screening goal.

The useful question is: **which declared sources, methods, conditions and use
terms accompany the 43 reference locations already linked to the 36 historical
material/model IDs?** This is a bounded documentary reconciliation, not a fresh
predictive study. The existing exposure history and scientific negatives remain.

## One reviewed pass, with honest exposure

Implementation should be one small standalone JSON projection and one review,
not a new reader framework or a sequence of per-field releases. Before it runs:
confirm the original container/field paths from the pinned schema and original
custody implementation; bind those paths, the two local object paths, exact
source bytes and output scope. The present field-presence booleans establish no
raw JSON pointer, and this design invents none. Existing source code may be read
for that implementation review later; none was reread for this preparation.

One invocation then reads each fixed object at most once, with its exact size
plus one byte as the read cap, and verifies size, SHA256 and Git blob identity
before strict UTF-8/JSON parsing. Use no network, imports of upstream loaders,
formula execution or external URI resolution. A modest fixed parser bound
(depth 32, at most 20,000 nodes, at most 16,384 characters in one string) is
adequate for a prospective small JSON pass; a bound violation stops, without
raising it automatically. Reject duplicate object keys, nonstandard nonfinite
constants and ambiguous container/field types. These are proposed engineering
limits, not observed properties of the unopened objects.

**Whole raw target-bearing bytes and whole parsed JSON become machine-exposed.**
That includes all 85 entry positions and their values, not only the 43 selected
locations. The initial custody operation already had mixed-JSON machine access;
this would be a new access and must have its own receipt. Public metadata is not
proof that a new byte read or parse succeeded.

For each selected location, the private documentary projection may expose the
literal citation, source locator and notes to the researcher, plus declared
material, structure, property, method and unit. Citation/URL/notes strings can
contain numeric outcomes, tolerances, conditions or scientific conclusions.
Their inspection is therefore **not target-free**; any such actual disclosure
must be recorded, without claiming a fresh holdout. The numeric value field,
other measurement arrays and the 42 unmatched entries are not intentionally
projected to the researcher. Withholding those fields cannot guarantee that
notes contain no outcomes. No model, exclusion or reference choice may respond
to any incidental values.

The public result should contain the 43-location provenance roster, original
36-ID candidate graph, short own-paraphrase notes, source/use-status declarations
and a list of unresolved identities. Publish necessary public scientific
citations; do not impose a blanket ban on references. Keep full citation/notes
projection and whole JSON objects ignored. Exclude raw property values,
residuals, ranks, fitted parameters, numeric reference-error comparisons,
full arbitrary notes, contact rosters, credentials or signed URLs. A human
publication review must verify any short selected citation text and remove
incidental outcome values from public prose without concealing their exposure.
No per-cell/target-value digest is needed; whole-file identities are sufficient.

The operation receipt should record exact code/input hashes, byte-read and
parse started/completed states, the public-metadata frame identity, selected
locations projected, researcher disclosure scope, and the first closed error
category. Partial work remains partial: no empty list or omitted field should
be presented as proof that bytes were never read. Technical count agreement is
not a scientific pass.

## Stop rules and the bounded deliverable

Stop on missing/changed objects, invalid identity, malformed/ambiguous JSON,
parser limits, changed ordinal/context or unsupported field layout. Retain the
first failure and do not refetch, widen the object set or adapt the parser to
observed outcomes. Missing citations or unresolved rights may yield a partial
roster with explicit UNKNOWN entries; they cannot produce invented matches or
scientific admission. Arbitrary notes with incidental numeric content are an
anticipated exposure, not a reason to silently call the output metadata-only.

After this one pass, issue one source-readiness decision. It can reconcile
**declared candidate provenance**, or identify a specific unresolved gate. It
cannot establish actual bound reference choice, numeric completeness/finiteness,
model checkpoint identity, latent physical accuracy, common-field validity,
hard discrepancy bounds, or future predictive transfer. No observed error may
choose among the competing vacancy references. Actual bound-choice/completeness
inspection, if still needed for an economical historical audit, requires a new
explicit scope; it is not automatic continuation of this one.

A finite comparison of stored labels does not require physical row independence
or per-test metrological intervals merely to define those labels. It does
require exact labels, complete frame/meaning, fixed rules and transparent
weights/costs. This pass answers only the provenance part. No labels are
compared, no census is executed and no source is admitted by this design.

[Source bindings](source-bindings.json) name the five already-public inputs
used here. The prospective graph is a metadata-derived artifact, not newly
acquired data, proof of reference correctness or an independent sample.
