# Rhizo documentary reference projector — generated-data candidate

This standalone candidate projects declared reference provenance from two fixed
retained JSON containers. It does not choose the reference used by an existing
bound record, inspect run/evidence objects, compare labels or admit a benchmark.
**Actual retained-source invocation has not occurred.** Only generated fixtures
may be executed during this preparation; root owns any later authorization.

The pre-implementation [scope](scope.json) binds the reviewed design and public
36-ID / 43-location / 172-edge frame. Original `projection_custody.py` confirms
zero-based `/entries` ordinals. Pinned upstream `binding.py` defines
`TargetFile.entries`, entry `material`, `structure`, `property`, `unit`, `method`
and `source.citation`, `source.doi_or_url`, `source.notes`. No upstream module is
imported. All selected context comparisons are literal: raw surface properties
`surface_energy_100/111/110` map to the frame's `gamma_100/111/110`; their unit
must be `J/m^2`, while vacancy must be `eV`. Method preference is not applied.

`inspect_synthetic(payloads, frame_raw)` takes a dictionary of the two fixed
repository paths to generated bytes and the exact pinned public frame. It
returns `(public_report, private_projection_or_null)`. It checks the frame and
all buffer types/lengths before reading buffer content. Known actual source
identities are rejected before JSON parsing. Fixture identities are computed
only as each buffer enters its recorded exposure stage. This is not an
independent identity check on generated fixtures.

The parser makes one JSON grammar pass per source. Root depth is one; depth is
at most 32. Nodes count each value and each object key and are capped at 20,000.
Decoded strings, including keys, are at most 16,384 Unicode characters. Strict
UTF-8, duplicate decoded keys, invalid JSON tokens, lone decoded surrogates and
ambiguous selected-field types fail closed. A valid surrogate pair is allowed.
Each input buffer is already capped at the expected file size; `scanstring`
temporarily decodes at most that bounded source before checking the tighter
string limit. This is not a claim of pre-allocation enforcement for each string.

JSON numeric tokens are scanned for lexical syntax and replaced with an opaque
marker. For example an arbitrarily large valid exponent is not evaluated.
There is no numeric completeness, finiteness, plausibility or uncertainty test.
All raw bytes, JSON token content and all 85 entry positions become machine
exposed if both files are read/parsed. Number-marker handling does not make this
target-free. The 42 unselected entries and non-documentary fields are parsed
within the bounds but not intentionally included in the private projection.

Missing/empty/null documentary fields receive explicit states. Other present
types block. A missing source block is treated as absent documentary fields;
a present non-object block blocks. Arbitrary extra source/entry fields are
unprojected. No structured condition/license path was invented: declarations
embedded in selected notes require human review, and condition and primary
source rights states remain `UNKNOWN`. Repository license notices are separate
documentary evidence, not a clearance of the cited primary sources.

Only after both containers, exact 57/28 entry counts and all 43 selected contexts
pass does the private projection become available. It contains literal
citation/locator/notes and declared context, **which may expose outcomes,
tolerances, conditions or scientific conclusions**. It cannot be called blind
or target-free. A processing failure returns no private projection but preserves
partial materialization and parse/read progress. The public report contains only
the existing frame, whole-file identities, fixed states and progress. It contains
no new raw source strings, numerical values or per-cell hashes. Necessary
scientific citations and short paraphrases may later be published only after
human review of the private projection; this program does not auto-publish them.

`run_synthetic_files(paths, payload_specs, frame_raw, output_slot)` exercises the
shared file path using generated temporary files. It rejects actual identity
specs and custody paths. Each spec has the same keys as `FILES`; fixed
path/family/entry-count fields remain unchanged, while fixture size/SHA256/Git
blob SHA1 describe generated bytes. `run_retained(root, manifest_path,
manifest_sha256)` is the future fixed-source wrapper and has not been invoked.
It requires the exact own-source hash, frame, source pins, fixed manifest/slot,
fixed original cache paths and exact 61,919-byte source identities. There is no
CLI, import-time acquisition, network, fallback or automatic retry.

Before source access the wrapper validates public bindings and exclusively
creates the output directory and reservation. It opens each fixed object once
with `O_NOFOLLOW`, checks a regular file, and performs one read of its expected
size plus one byte. It validates size/SHA256/Git blob identity on the same
immutable bytes before parsing. Source guards are rechecked before each read
and output. The fixed slot remains reserved on failure; repeated invocation
cannot overwrite it. Normal directory ownership and the controlled runtime are
assumed; this is not an arbitrary hostile-process security boundary.

The wrapper writes private output only after complete projection, then the
public receipt, using exclusive files. A failed output write/close may leave a
partial private file: the closed failure records that possibility and preserves
an earlier processing reason. A successful private write followed by public
failure remains explicitly disclosed. Actual researcher inspection is
`NOT_OBSERVED_BY_THIS_PROGRAM`; writing/returning the projection makes these
potentially target-bearing strings available and cannot certify non-exposure.

Every result keeps actual bound reference choice `UNKNOWN`, no chosen method,
no numeric completeness claim, zero fits/splits/label comparisons and scientific
status `NOT_ADMITTED`. The historical figure map remains distinct from the
re-relaxed calculator. Generated passes demonstrate specified software behavior
only; no physical or new scientific result follows.
