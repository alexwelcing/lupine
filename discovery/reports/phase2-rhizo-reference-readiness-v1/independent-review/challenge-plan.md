# Independent Rhizo projector challenges

Prepared before the candidate source was available. This lane uses the pinned
public reference frame and generated JSON only. Actual source objects, custody
captures, run/bound records, network and production invocation are excluded.

The review will challenge these distinct invariants once the author freezes the
source and exact API. These are proposed checks, not executed passes.

1. The private documentary result preserves all 43 frozen locations and 172
   original graph edges, with actual bound reference choice UNKNOWN. No source
   selection, deduplication or experimental-independence claim is introduced.
2. Selected citation/URL/notes canaries are present only in the private result;
   ignored fields, unselected entries and value tokens never appear there or in
   the public projection. Public whole-file identities are allowed and are not
   evidence that the file stayed unexposed.
3. Within admitted size/structural bounds, changing numeric lexemes or opaque
   fields cannot change provenance conclusions. Whole-input hashes and byte
   counts may change and must be preserved rather than suppressed.
4. Duplicate object keys, including escaped equivalents, reject. JSON numeric
   syntax is distinct from physical finiteness: forbidden NaN/Infinity literals
   reject, while legal large exponent tokens are not converted into floats or
   described as validated measurements.
5. UTF-8, JSON syntax and parser depth/node/string limits obey the frozen
   contract. Challenge exact boundaries and adversarial nested/long-token forms
   without changing caps after a failure.
6. Context mismatch, missing/ambiguous structural fields and incorrect
   property-to-unit mapping block rather than fuzzy-match. Missing optional
   documentary fields remain explicitly unknown; types follow the held API.
7. A late second-object or selected-location failure clears the entire private
   projection while preserving first-object byte/parse and partial second-object
   exposure. No empty projection is interpreted as no source access.
8. A fixture wrapper checks code/frame/input identity and reserves an exclusive
   output location before source access. Occupied slots, symlinks, wrong byte
   identity and partial read/write/close failures retain first evidence. Exact
   permitted fixture paths replace all real custody paths before any invocation.
