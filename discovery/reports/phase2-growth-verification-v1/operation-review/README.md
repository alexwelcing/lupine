# Prepared independent G30/G31 operation audit

This is prospective source preparation. The operation auditor and its recorder
have not been imported or executed. `bindings.unbound.json` deliberately contains
no actual commit, recorder, CI, package or operation-outcome binding. It cannot
launch an audit because its status is `UNBOUND`. The separately authorized
retained-artifact audit in `phase2-growth-artifact-review-v1` is a different,
completed task; it is not an invocation of this operation auditor.

The new auditor preserves the prior G29 public-evidence checks with explicit
adaptation to G30 and G31. [check-adaptation.json](check-adaptation.json) maps all
98 prior `check` call sites to 176 new sites: 53 old calls have identical ASTs;
45 have explicit before/after mappings. Every old check is mapped. These are
static call-site counts, not executed checks or a test-pass total. Original
source and a full diff are retained. Static parse and compilation were performed
without importing or running the prepared modules.

The shared gates require exact published HEAD and clean worktree, all 332 runtime
files against the manifest and committed Git bytes, the original successful
four-job push CI, package and strict-verifier logs, exact retained artifact
identities, both independent artifact reviews and their completed recorded
processes. The additive audit must preserve 326 earlier runtime files, identify
the six additions and bind all eight reviewed source/test/contract files. Gate
times must precede operation preflight and the audit itself.

Each stage requires its fixed two operation slots, exact source-group identity,
root-bound final recorder digest and commit literal, sequential timestamps,
successful source holds, exit 2, empty stderr, canonical public output identical
to recorded stdout, and exact recorded exposure. A conflicting `stopped.json`,
partial result, timeout, guard failure or cleanup failure cannot pass. Persisted
output alone cannot mask an error returned after a descriptor-close failure.
Final replay equality means computational replay, not scientific replication.

G30 permits its three closed shape outcomes, including signature or padding
negatives. It checks the inherited complete G29 field walk and all new shape
booleans and interpretation flags. The fixed public G29 prerequisite remains
exactly bound; its field-header checks are preserved, while G30's output must
omit that numeric list. If the completed G30 pair is negative, G31 must have no
operation directory or public slot; the audit reports `NOT_RUN_NEGATIVE_G30`.

For a `both` audit after a matching G30 pair, G31 preflight must follow G30 final
completion and bind both public shape receipts plus the final result. G31's
nested selected exposure differs only in the three acquisition flags because
it receives an already-read buffer. The auditor checks closed structural/XML
negatives, central-preflight-before-own-open semantics, local progress counts,
the ordered four-member XML lists and partial exposure. A valid declared-profile
envelope may disclose only the existing documentary-role projection. Scientific
counts remain null, fitting/splitting remain zero, and initial-padding semantics
remain unbound. No physical, semantic or sampling-independence claim follows.
These checks establish the declared receipt and progress constraints, not a
classifier-equivalence proof or reachability proof for every allowed
reason/progress combination. Interpretation of an eventual observed path still
needs to be tied to the exact source and retained evidence.

Only five fixed public custody receipt paths are readable: G29 run 1 and the
two G30/G31 slots. Object and capture paths are always refused. Other evidence
must be bounded regular files within this checkout, with symlink resolution
unchanged. Repeated reads cannot replace earlier hashes, and every input is
rehash-checked at completion. Public source is parsed through AST literals and
key names only; no production module, runtime enumerator or source guard is
imported or invoked. Git access is local `show`, `status` and `rev-parse`, with
a timeout; remote state is recorder evidence, not a fresh network check here.

Root must supply a separate final binding record using the unbound template's
schema and `status: FINAL_BOUND_OPERATION_AUDIT`. Its required values are the
exact published commit, final reviewed eight-file pin-record digest, both
commit-bound operation recorder digests, and exact hashes for the seven fixed
CI/package/artifact-review/artifact-execution gate files. Do not replace or
silently relabel the retained unbound template. No outcome reason is configured;
actual results are read and checked against the predeclared allowed states.

After independent source review and root authorization, invoke the recorder
with the final binding-file hash, reviewed auditor hash, operator identity, and
`--stage shape` or `--stage both`. Shape-only invocation explicitly labels G31
`NOT_AUDITED_BY_SHAPE_ONLY_INVOCATION` after a match; it does not claim G31 absence
or readiness. Each stage has exclusive output names, so previous attempts are
never overwritten or automatically retried. A later combined audit has separate
outputs from an earlier shape-only audit.

The recorder verifies its auditor and final bindings before and after the child,
records timeout/launch/nonzero outcomes and log hashes, and checks a zero-exit
audit's scoped result. The operator must separately verify the recorder's own
reviewed hash before launch. Early filesystem errors or interruption can leave
an incomplete record; missing final evidence is not success. The 180-second
direct-child timeout is not a process-group or output-quota guarantee. This
controlled workflow is not a hostile filesystem or hostile-code boundary.
