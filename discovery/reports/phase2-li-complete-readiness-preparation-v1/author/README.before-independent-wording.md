# Generated complete Li readiness candidate

This is one generated-only implementation of the accepted bounded package → documentary → complete-frame route. It makes no production call and refuses the known actual Li source identities. A completed frame remains `BLOCKED_SCHEMA` for numerical/scientific use. `METADATA_FRAME_READY_FOR_SEPARATE_LABEL_RULE` permits consideration of a separately frozen label rule; it is not a valid-pair count, validated benchmark, or declaration of scientific independence.

The accepted design is `../phase2-li-complete-readiness-design-v1/{README.md,proposal.json}`, v2 reviewed by `../phase2-li-complete-readiness-design-review-v1/review.json`. Root's `../phase2-li-complete-readiness-root-v1/implementation-scope.json` authorizes this generated implementation. The original 335 runtime files remain frozen by `scope.json`; no existing profile was changed.

## Pure calls and wire format

`inspect_synthetic_layout(raw, *, expected_diagnostic)` returns complete package metadata and G32 documentary layout. `inspect_synthetic_documentary(raw, binding, *, expected_diagnostic, prior_layout)` binds reviewed documentary definitions. `inspect_synthetic_frame(raw, binding, *, expected_diagnostic, prior_layout, prior_documentary)` validates a complete metadata frame. `raw` is exact immutable `bytes`; the same object is supplied to the header replay and new package header parse.

`interface.final-v3.json` specifies binding shapes. `report-shapes.json` specifies projected payloads and lifecycle semantics. `canonical(value)` is **compact sorted-key `ensure_ascii=True` JSON, followed by one LF, encoded as ASCII**. Receipt digests include that LF. Bindings and reports must use plain bounded JSON types; custom containers, excess keys, depth, nodes, nonfinite numbers, and oversize strings/serialized objects fail closed.

The generated expectation is an explicit complete G34 synthetic report frozen outside the tested candidate. Candidate compares the complete canonical replay and then requires the sole `MEMBER_KIND_PROFILE/member_kind/ZIP_LAYOUT_UNSUPPORTED` rejection, other 31 families fully checked/pass without partials, selected growth match and successful cleanup. Expectation mismatch occurs before any member opening. The author fixtures use the unchanged diagnostic as an external header oracle; the independent reviewer manually declares the projection from independently packed fixtures. The future production adapter must accept no caller expectation and require the exact fixed actual prerequisite/replay projection.

## Documentary and frame premises

Selected coordinates, meanings, units, exact `allowed_texts`, and disclosure flags must be frozen from already permitted documentary evidence. No undeclared source preview may populate them. `DOCUMENTARY` plus a text match yields `MANIFEST_ASSERTION`, not parser-derived scientific meaning. A required unresolved mapping or mixed field blocks. Optional unresolved fields retain unknown without text. Selected merged cells block, including the top-left cell. Only plain inline strings or controlled plain shared strings are decoded as selected text; formulas, cached numeric interpretations, and rich-text interpretation do not supply documentary metadata. Only approved `disclose_text=true` definitions/citations are projected.

Frame binding contains the exact documentary binding for same-buffer revalidation, complete workbook-sheet coverage (two exact documentary roles, record roles, and explicitly justified exclusions), and every explicit record-row classification. No whole sheet or explicit row may silently disappear. Empty XML rows stay visible. A BLANK assertion requires no explicit cells. Headers, notes, summaries, DATA assignments, row units, and provenance metadata meanings remain manifest premises. Metadata columns cannot overlap endpoint columns. Endpoint output is only cell presence, declared storage type, and formula-element presence; no endpoint value or numerical validity is projected. Shared strings are opened only if a selected textual cell requires them; full selected-sheet character data is nevertheless decoded in process.

Required metadata gaps, unresolved rows, unjoined reference keys, and unknown row units retain a complete negative frame as `NO_GO_UNRESOLVED_PREMISE`. Provenance overlap is exact declared key comparison against a supplied authenticated-manifest premise. Neither a matching key nor a DOI establishes physical measurement identity, same specimen, independence, or a scientifically valid pair. All counts are physical/structural, and `paired_count` stays null.

Prior receipts have a closed historical shape, source/phase/success/cleanup and canonical hash checks. Prior package, layout, and documentary payloads are recomputed on this same buffer and compared exactly. Historical lifecycle fields are not treated as current events. A future production adapter must independently authenticate fixed prior receipts; caller hashes and authentication flags are only explicit premises in pure tests.

## Exposure, failures, and bounds

`whole_buffer_supplied` records source identity validation. `header_replay_started/completed` record the earlier payload-free G34 header replay; completed means the routine returned, including a rejected/mismatched replay, not that it qualified. The `archive_*` flags describe the **separately owned new package archive only**. A replay mismatch can therefore have replay flags true and package archive flags false. Member/decompression/UTF-8/XML counters describe subsequent selected package/documentary/frame operations. A partial read or parse retains started counters and exposure. This is not target-free access: source identity covers the whole buffer and worksheet XML processing can expose character data in machine memory.

Mechanical, binding, parser, cleanup, or public-size failure clears package/roles/documentary/frame atomically while retaining closed exposure and reason fields. A failed archive close preserves its prior validation reason. A completed negative frame retains its complete row accounting. Exceptions expose only closed reason codes, not arbitrary source strings. There is one finite route: unsupported or unbound actual evidence must retain a terminal NO_GO; no automatic names, fields, parser broadening, or value extraction follows.

Prospective caps remain: 183,878 source bytes; 128 members; 256-character member names; 65,535-byte local extras; metadata 2 MiB each/8 MiB total; documentary sheets 2 MiB each/4 MiB total; frame sheets separately 2 MiB each/4 MiB total; XML depth 64, nodes 65,536/member, attributes plus namespace declarations 32, names 256, attribute values 1,024; 4,096 type declarations and relationship edges; 8,192 documentary cells/role and 1,024 merges/role; 2 MiB shared strings, 16,384 entries, 65,536 chars/item; 1,024 selected fields of at most 2,048 chars; 8,192 frame rows and 65,536 explicit frame cells; 2 MiB public output. No cap was increased from the accepted design.
