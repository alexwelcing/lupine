# Independent source argument for the separate envelope profile

The new profile depends on the existing fixed G29 public receipt and immutable capture/object identity, then repeats G29 and the reviewed G30 predicate on the same buffer. It does not assume or manufacture a future G30 receipt. In production, the initial selected span must again have exactly the frozen A220/516 list. The synthetic interface deliberately permits other bounded eligible lengths for generated tests while retaining the known-real-source refusal. No actual payload has been read by this review.

Initial shape checking and complete archive validation are different stages. The selected G29/G30 result establishes one first span only. The new full traversal checks every local entry, retaining the prior name, type, flag, method, size, CRC, version, timestamp, offset, directory, required-member and central-extra predicates. A static AST comparison verifies the old body after only the declared local-extra alternative, newly approved central preflight call, and exposure/ownership scaffolding are removed. That comparison does not prove the added code; the separate source argument and generated tests address it.

The first author execution exposed an inherited truncation gap: a final central comment-length declaration of one with no body byte could be accepted when ZipFile returned an empty short read. The first source, failed assertion and logs remain preserved. Root approved a narrow additional preflight before the new archive opens. It checks strict bounded integer directory/count inputs, exact directory end, at most 128 fixed 46-byte records, each central signature and complete declared variable span, and zero declared extra/comment lengths. The cursor increases by 46 plus bounded unsigned lengths, so the loop terminates and cannot read beyond the directory. Exact final cursor equality rejects unconsumed tails. It reads fixed numeric fields without decoding names. Existing ZipInfo-based predicates still run afterward. The original failed test remains AST-identical in the later passing author suite.

For each nonempty local span, the new helper first bounds the range, requires at least a complete four-byte TLV header, checks ID A220 and exact framing, and requires at least four body bytes. It decodes signature and initial PadVal as two little-endian unsigned words. Only a matching signature permits the bounded scan of all remaining bytes. Every byte must be NUL; no PadVal/current-length or history inference is made. The complete span must be one record, so duplicate, unknown or trailing records cannot be silently skipped. The caller only invokes this helper after the unchanged local-header bounds and consistency checks pass. Entries with zero local-extra length retain the previous path, but an archive with no positive span fails the separate initial selected-span gate.

The profile does not patch the previous reader or any global helper. The archive holder is populated immediately after successful read-only in-memory ZipFile construction, before infolist or later checks can fail. The owning inspection function closes it on every header/XML path. New counters distinguish started areas, completed valid areas, interpreted fixed words and started/completed full padding scans. A malformed later entry can therefore retain exposure from earlier entries. The nested selected-growth flags describe that initial stage, while the outer report accounts for the whole-source read and subsequent profile work.

Only after every header check succeeds can the unchanged four envelope XML helpers run. They retain their original member allowlist, resource bounds, relationship/workbook parsing and documentary-role projection. The new parser does not decompress worksheet or shared-string components, inspect cell values, execute formulas or derive eligibility. XML started/completed arrays survive later failures. Cleanup failure replaces the engineering success with a fixed blocked status, clears envelope acceptance/projection, preserves the previous validation reason, and detaches the owned in-memory handle to prevent a normal destructor retry from disclosing a raw exception. This is a controlled Python workflow, not protection against arbitrary monkeypatches or hostile code.

The final profile-acceptance flag requires completed envelope checks and successful explicit close. Guard/write/directory-close failures clear that acceptance while retaining current exposure and any earlier selected-span result. A completed-slot replay is refused before a new private read and writes are exclusive; this is a serialized operation, not a concurrency lock. If writing succeeds before descriptor close fails, the already-written file and returned blocked report can differ and both must be retained.

Envelope compatibility remains separate from scientific validity. Even a complete match leaves scientific schema blocked, row/pair/group/overlap counts null and fits/splits zero. The profile says nothing about producer authenticity, normative PadVal history, all possible ZIP/OPC features, numeric endpoint meaning, row eligibility, independent sampling or recommendation quality. Runtime tests are generated fixtures with complete private-I/O/guard mocks; actual operations remain parent-owned and separately gated by exact source publication, CI and retained artifact audit.
