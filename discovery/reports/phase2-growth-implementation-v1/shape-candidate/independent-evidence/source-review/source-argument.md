# Source argument and limits

The reviewed implementation is a controlled workflow for a single already captured object. Its hashes bind software and public receipts; they do not prove physical truth, origin independence, or correctness against hostile Python code. The G29 public prerequisite reports one selected outer header with ID `0xA220` and body size 516. It reports no interpretation of that body. The new operation therefore still needs to establish the proposed shape on verified bytes.

The public production entry point first restricts the run to the two fixed slots. Its source context requires its canonical pathname, the unchanged predecessor guard, the exact closed predecessor identity groups, its own four files equal to committed and indexed bytes, and a final HEAD agreement. The predecessor maps contain 25 distinct frozen public files. The new prerequisite has a fixed whole-receipt digest and producer and checks the declared completed inventory, source identity, selected header list, and exposure. This occurs before private capture or object reads. The new wrapper then uses the unchanged exclusive destination and original capture/object checks.

The whole verified object is passed to unchanged G29 inspection again. A historical public receipt alone does not authorize a payload result: the same buffer must yield a complete field list equal to the frozen single-record list. Other field lists are blocked before the new payload helper. The unchanged predecessor only completes after the precise first local-extra rejection and successful archive cleanup, and it publishes its list only after consuming the entire selected span. The later locator therefore addresses that same first span under the predecessor's established contiguous-prefix conditions.

The extracted payload predicate is AST-identical to the previously reviewed pure implementation. It bounds and checks the selected span, requires one outer `0xA220` record and at least four body bytes, decodes two little-endian unsigned words, withholds the initial-padding word, compares the signature to `0xA028`, and visits every remaining byte for NUL membership. It does not recursively parse, search, decode names or values, decompress a ZIP member, decode XML, or inspect a worksheet. There is no asserted equality between initial PadVal and current padding length. A successful comparison discloses the fixed signature match and all-NUL result through booleans; it is not a claim that those facts remain concealed.

The wrapper retains the existing report object across source reads, predecessor inspection, predicate execution, serialization and descriptor cleanup. New guard failures clear its shape conclusions while preserving current exposure. A failed read after it starts leaves completion false and whether target-bearing bytes were read unknown. A completed whole-object read is declared even if identity subsequently fails. A successful output write followed by destination-descriptor close failure can leave a file containing the earlier result while the returned report is blocked; neither report may silently replace the other in operational evidence. An existing completed output slot blocks a later sequential replay before the private read, and exclusive creation prevents overwriting. This is not a concurrency lock: simultaneous invocations could both pass the earlier absence check before either writes. The controlled operation must remain serialized.

The completed operation continues to report `BLOCKED_SCHEMA`, archive acceptance false, scientific evaluation blocked, and null scientific counts. The result is only a shape predicate on the first selected extra span. It does not establish the entire ZIP/OPC profile, later spans, workbook roles, numeric meanings, row eligibility, sampling independence, or recommendation quality. Synthetic tests and source identity cannot supply any of those conclusions.

This argument is based on source inspection and the named public receipt. The separate executable review uses synthetic fixtures and complete custody stubs. Actual production invocation remains outside this review and requires the parent-owned source publication, CI, package and operational evidence gates.
